# 🔴 Исправление: Дублирование логики решений (Ключевая причина №3)

## Проблема

Была дублирующая логика обработки решений на клиенте и сервере:

### До исправления:
1. **Локально на клиенте**: `submitDecision()` → `triggerReveal()` → `processDecisions()`
   - Обрабатывала решения сразу при получении всех голосов
   - Меняла состояние на EXPEDITION или ROUND_END

2. **С сервера**: `roomState.decisionsResult`
   - Переходила на RESULTS_PHASE
   - После 3 сек применяла решения
   - Меняла состояние на EXPEDITION или ROUND_END

### Результат конфликта:
```
DECISION_PHASE → processDecisions() [локально] → EXPEDITION
        ↓
decisionsResult приходит → RESULTS_PHASE → EXPEDITION
```

Это создавало **непредсказуемые переходы состояний** и скачки фаз.

## Решение

### ✅ Что изменено:

1. **Удалена функция `processDecisions()`** - локальная обработка решений больше не вызывается

2. **Изменена `triggerReveal()`** - теперь просто ждёт от сервера:
   ```typescript
   const triggerReveal = (decisions: Record<string, 'stay' | 'leave'>) => {
     // НЕ обрабатываем локально, только отправляем на сервер
     console.log('Waiting for server to process decisions...');
     // Ждём roomState.decisionsResult от сервера
   };
   ```

3. **Сервер - единственный источник истины**:
   - Собирает все решения
   - Применяет их (рассчитывает очки, определяет вышедших)
   - Отправляет `decisions_processed` со всей информацией
   - Клиент только отображает результаты

### Поток данных теперь:

```
Client: submitDecision() 
  → Server: слушает все решения
    → Server: обрабатывает, рассчитывает
      → Server: отправляет decisions_processed
        → Client: roomState.decisionsResult
          → Client: отображает RESULTS_PHASE
            → Client: переходит на EXPEDITION или ROUND_END
```

## Преимущества

✅ Единственный источник истины (сервер)  
✅ Нет конфликтов логики между клиентом и сервером  
✅ Все клиенты видят одинаковые результаты  
✅ Нет непредсказуемых скачков состояний
